# a-ssh Android SSH 客户端 — 开发文档 (v2)

> 本文档面向 **v2 范围(功能 7:WebDAV 同步)**,在 v1(功能 1–6)已落地的基础上增量开发。
> 阅读前置:先读完 `开发文档-v1.md`,理解其数据层(Room 四张表)、`CryptoManager`(Keystore 字段级加密)、Repository 与模块划分。本文所有设计都建立在 v1 的「核心 SSH/终端不感知上层功能」「敏感字段密文常驻」两条原则之上。

## 0. v2 目标与边界

| 项 | 内容 |
|---|---|
| 核心功能 | 把本地配置(服务器/私钥/自定义命令/设置)通过 **WebDAV** 协议同步到用户自建或第三方网盘(Nextcloud / 坚果云 / Synology / 自建 nginx-dav 等)|
| 不做 | 不做实时多端协同;不做服务端;不依赖任何 a-ssh 官方云。用户完全自带 WebDAV 端点 |
| 同步内容 | Host / Key / Command / 全局设置。**KnownHost 指纹默认不同步**(属设备本地信任,见 §6.3)|
| 同步模型 | 手动 + 可选自动(按间隔/启动时)。冲突走「基于版本向量 + 时间戳」的合并,默认「最后写入获胜」可被用户覆盖 |
| 安全基线 | 私钥/密码这些 v1 用 Keystore 加密的字段,**绝不以设备 Keystore 密文上传**(那密文换设备无法解密)。改为用**用户同步口令**派生密钥重新加密后上传。见 §4,这是 v2 最关键的设计点 |

### 为什么 WebDAV 而不是自建同步服务
- 零服务端运维:用户已有的网盘即可。
- 协议简单:HTTP 之上的 `PROPFIND/GET/PUT/DELETE/MKCOL/LOCK`,一个 OkHttp 就能封。
- 符合 v1「不绑定官方云」的隐私取向。

## 1. 关键决策(v2 新增)

| 决策点 | 选择 | 理由 |
|---|---|---|
| WebDAV 客户端 | 自封装 OkHttp(不引第三方 dav 库) | dav4jvm 等库可选,但 WebDAV 我们只用到少数几个动词,自封更可控、依赖更少 |
| 同步数据格式 | 单个加密 JSON 包(`assh-vault.json.enc`) | 一个文件原子上传/下载,避免多文件半同步态;内部是结构化 JSON |
| 同步加密 | 用户**同步口令** → Argon2id/PBKDF2 派生 → AES-256-GCM | 跨设备可解密的前提是密钥不绑定单台设备的 Keystore |
| 冲突策略 | 每实体带 `updatedAt` + `syncRev`;包级带 `vaultVersion` | 既能整体版本比对,又能字段级合并 |
| 自动同步 | WorkManager 周期任务 + 手动触发 | 受电量/网络约束,系统友好 |

## 3. WebDAV 客户端封装

### 3.1 用到的 HTTP 动词
| 动词 | 用途 |
|---|---|
| `PROPFIND` (Depth: 1) | 列目录 / 探测文件是否存在、拿 ETag 与 Last-Modified |
| `GET` | 下载同步包 |
| `PUT` | 上传同步包 |
| `MKCOL` | 创建同步目录(如 `/a-ssh/`)|
| `DELETE` | 删除(重置同步时)|
| `LOCK`/`UNLOCK` | 可选,防并发写;多数网盘支持有限,v2 用 ETag 乐观锁替代,见 §5.3 |

### 3.2 WebDavConfig 实体
WebDAV 端点凭据本身也是敏感信息,沿用 v1 的 `CryptoManager` 设备级加密存 Room(它不需要跨设备同步,属于本设备配置):
```kotlin

    val username: String,
    val encPassword: ByteArray,           // 设备 Keystore 加密
    val remoteDir: String = "a-ssh",      // 远端子目录
    val autoSync: Boolean = false,
    val intervalMinutes: Int = 60,
    val lastSyncAt: Long? = null,
    val lastRemoteEtag: String? = null    // 乐观锁用
)
```

### 3.3 WebDavClient 骨架
```kotlin
class WebDavClient(private val cfg: ResolvedWebDavConfig) {
    private val http = OkHttpClient.Builder()
        .connectTimeout(15, TimeUnit.SECONDS)
        .readTimeout(30, TimeUnit.SECONDS)
        .build()

    private fun urlOf(name: String) =
        cfg.baseUrl.trimEnd('/') + "/" + cfg.remoteDir + "/" + name

    private fun auth() = Credentials.basic(cfg.username, cfg.password)

    suspend fun ensureDir() = withContext(Dispatchers.IO) {
        val req = Request.Builder()
            .url(cfg.baseUrl.trimEnd('/') + "/" + cfg.remoteDir + "/")
            .method("MKCOL", null)
            .header("Authorization", auth())
            .build()
        http.newCall(req).execute().use { /* 405=已存在,忽略 */ }
    }

    /** 返回 (bytes, etag);文件不存在返回 null */
    suspend fun download(name: String): Pair<ByteArray, String?>? = withContext(Dispatchers.IO) {
        val req = Request.Builder().url(urlOf(name))
            .header("Authorization", auth()).get().build()
        http.newCall(req).execute().use { resp ->
            if (resp.code == 404) return@use null
            if (!resp.isSuccessful) error("download failed: ${resp.code}")
            resp.body!!.bytes() to resp.header("ETag")
        }
    }

    /** 带乐观锁上传:ifMatch 为上次已知 etag,远端变了则返回 412 */
    suspend fun upload(name: String, data: ByteArray, ifMatch: String?): String? =
        withContext(Dispatchers.IO) {
            val b = Request.Builder().url(urlOf(name))
                .header("Authorization", auth())
                .put(data.toRequestBody("application/octet-stream".toMediaType()))
            ifMatch?.let { b.header("If-Match", it) }
            http.newCall(b.build()).execute().use { resp ->
                if (resp.code == 412) throw RemoteChangedException()
                if (!resp.isSuccessful) error("upload failed: ${resp.code}")
                resp.header("ETag")
            }
        }
}
```
> 注:部分网盘(坚果云)不返回稳定 ETag,届时降级用 `Last-Modified` 或在包内自带 `vaultVersion` 做并发检测(见 §5.3)。

### 3.4 连通性测试
设置页提供「测试连接」:`PROPFIND` 根目录,成功(207 Multi-Status)即提示 OK,失败把 HTTP 状态/异常呈现给用户。注意区分:401(认证失败)、404(路径错)、SSL 错误(自签证书需提示用户)。

## 4. 同步包(Vault)设计 ★核心

### 4.1 VaultSnapshot / DTO
同步包是**与设备无关的明文结构**(在内存中),序列化后**整体用同步口令加密**再上传。它绝不含 v1 的 Keystore 密文。

```kotlin
@Serializable
data class VaultDto(
    val schema: Int = 1,
    val vaultVersion: Long,            // 单调递增,每次成功推送 +1,用于并发检测
    val exportedAt: Long,
    val deviceId: String,              // 哪台设备最后写的
    val hosts: List<HostDto>,
    val keys: List<KeyDto>,
    val commands: List<CommandDto>,
    val settings: Map<String, String>
)

@Serializable
data class HostDto(
    val uuid: String,                  // ★ 跨设备稳定主键(见 §4.3)
    val label: String, val host: String, val port: Int,
    val username: String, val authType: String,
    val password: String? = null,      // 明文(整包会被加密),无密码则 null
    val keyRef: String? = null,        // 引用 KeyDto.uuid,而非 v1 的本地自增 id
    val charset: String, val initialCommand: String?,
    val updatedAt: Long, val deleted: Boolean = false  // 软删除,见 §5.4
)

@Serializable
data class KeyDto(
    val uuid: String, val alias: String, val keyType: String,
    val privateKey: String,            // 明文 PEM(整包加密保护)
    val passphrase: String? = null,
    val publicKey: String? = null,
    val updatedAt: Long, val deleted: Boolean = false
)

@Serializable
data class CommandDto(
    val uuid: String, val label: String, val command: String,
    val appendEnter: Boolean, val hostRef: String? = null,  // 引用 HostDto.uuid
    val updatedAt: Long, val deleted: Boolean = false
)
```

### 4.2 导出/导入流程
```
导出: Room 实体 ──解密(设备Keystore)──> 明文 ──组装──> VaultDto
       ──kotlinx.serialization──> JSON 字节
       ──VaultCrypto.encrypt(同步口令)──> assh-vault.json.enc ──PUT──> WebDAV

导入: GET ──> assh-vault.json.enc ──VaultCrypto.decrypt(同步口令)──> JSON
       ──反序列化──> VaultDto ──合并(§5)──> 写回 Room(敏感字段重新用设备Keystore加密)
```
关键:**明文私钥/密码只在内存的 VaultDto 中短暂存在**,加密上传后立即丢弃引用;导入解密后同理,写回 Room 时立刻转成设备 Keystore 密文。

### 4.3 跨设备稳定主键(必须改造 v1)
v1 实体用 `autoGenerate` 自增 `Long id`,**跨设备会冲突**(两台设备的 id=1 是不同 host)。v2 必须给每个可同步实体加一个稳定 `uuid`:

```kotlin
// v1 实体增加字段(需要 Room migration v1→v2)
val uuid: String = UUID.randomUUID().toString()
```
- 本地仍用自增 `id` 做关系/外键(性能好),`uuid` 仅用于同步匹配。
- Host→Key 的引用在本地是 `keyId: Long`,导出时翻译成 `keyRef: KeyDto.uuid`,导入时再翻译回本地 id。Repository 负责这层 id↔uuid 映射。
- **迁移**:`AsshDatabase` version 1→2,`Migration` 给老数据补 uuid(`ALTER TABLE ... ADD COLUMN uuid TEXT`,然后用一次性逻辑为每行填 `randomUUID`)。

### 4.4 VaultCrypto — 同步口令派生
```kotlin
object VaultCrypto {
    // 包头: [magic "ASV1"(4)][saltLen(1)][salt(16)][iv(12)][ciphertext+tag]
    private const val SALT_LEN = 16
    private const val IV_LEN = 12

    fun deriveKey(passphrase: CharArray, salt: ByteArray): SecretKey {
        // Argon2id(BouncyCastle):iterations=3, memory=64MB, parallelism=2, out=32B
        val gen = Argon2BytesGenerator()
        gen.init(Argon2Parameters.Builder(Argon2Parameters.ARGON2_id)
            .withSalt(salt).withIterations(3)
            .withMemoryAsKB(65536).withParallelism(2).build())
        val out = ByteArray(32)
        gen.generateBytes(passphrase, out)
        return SecretKeySpec(out, "AES")
    }

    fun encrypt(plain: ByteArray, passphrase: CharArray): ByteArray {
        val salt = SecureRandom().generateSeed(SALT_LEN)
        val key = deriveKey(passphrase, salt)
        val cipher = Cipher.getInstance("AES/GCM/NoPadding")
        cipher.init(Cipher.ENCRYPT_MODE, key)
        val iv = cipher.iv
        val ct = cipher.doFinal(plain)
        return MAGIC + byteArrayOf(SALT_LEN.toByte()) + salt + iv + ct
    }

    fun decrypt(blob: ByteArray, passphrase: CharArray): ByteArray {
        // 校验 magic、读 salt/iv、deriveKey、GCM 解密;口令错→AEADBadTagException→提示"口令错误"
        ...
    }
}
```
- **同步口令 ≠ 设备解锁口令**。它是用户为「这套配置库」设的密码,换新设备时输入它即可解出全部配置。
- 口令本身**不存任何地方**(可选:用 v1 Keystore 缓存以便自动同步,但要让用户知情)。
- Argon2id 参数(64MB 内存)在低端机可能偏慢,提供降级档(memory=32MB)。

## 5. 同步引擎与冲突合并

### 5.1 SyncEngine 编排
```kotlin
class SyncEngine(
    private val dav: WebDavClient,
    private val codec: VaultCodec,
    private val syncable: Syncable,          // app 提供的 Room 导入导出
    private val localMeta: SyncMetaStore     // 存 lastVaultVersion / deviceId
) {
    suspend fun sync(passphrase: CharArray): SyncResult {
        dav.ensureDir()
        // 1. 下载远端
        val remote = dav.download(VAULT_NAME)?.let { (bytes, etag) ->
            codec.decode(bytes, passphrase) to etag
        }
        // 2. 导出本地
        val local = syncable.exportSnapshot().toDto(localMeta)
        // 3. 合并
        val merged = MergeStrategy.merge(local, remote?.first)
        // 4. 写回本地
        syncable.applySnapshot(merged.toSnapshot())
        // 5. 推送(版本+1,带 ifMatch 乐观锁)
        merged.vaultVersion = (remote?.first?.vaultVersion ?: 0) + 1
        val bytes = codec.encode(merged, passphrase)
        val newEtag = dav.upload(VAULT_NAME, bytes, ifMatch = remote?.second)
        localMeta.save(merged.vaultVersion, newEtag)
        return SyncResult.Ok(merged.stats())
    }
}
```

### 5.2 MergeStrategy — 实体级合并
对每类实体按 `uuid` 做三方匹配(本地、远端):
```
for uuid in (localUuids ∪ remoteUuids):
    l = local[uuid]; r = remote[uuid]
    when:
        l!=null && r==null  -> 保留 l(本地新增,远端还没有)
        l==null && r!=null  -> 取 r(其他设备新增)
        both != null        -> 取 updatedAt 更大的(最后写入获胜 LWW)
        都标记 deleted        -> 删除
```
- **默认 LWW(Last-Write-Wins)**,基于 `updatedAt`(毫秒)。
- 用户可在设置里改成「冲突时询问」:检测到 both 修改且内容不同 → 弹列表让用户逐条选本地/远端。v2 先实现 LWW,「逐条询问」作为可选增强。
- **时钟漂移**风险:LWW 依赖设备时间。多设备时间不准会误判。缓解:导出时记录 `exportedAt`,合并时若两端时间差异常大给用户提示。

### 5.3 并发写保护(乐观锁)
- 上传带 `If-Match: <lastEtag>`。若期间别的设备已推送,远端 ETag 变了 → 返回 412 → 本次先**重新下载合并再推送**(重试一次)。
- 不支持 ETag 的网盘:退化方案——下载到的 `vaultVersion` 与本地记录的 `lastVaultVersion` 不一致即说明远端有更新,先合并;推送后保存新 version。存在极小的「同一秒双推」竞态,对个人单人多设备场景可接受。

### 5.4 删除处理(软删除/墓碑)
- 直接物理删除会导致「这台删了,同步时被另一台的旧记录复活」。
- 方案:同步实体加 `deleted: Boolean` + `updatedAt`。删除即置 `deleted=true` 并更新时间,同步出去;合并时 `deleted` 也参与 LWW。
- **墓碑清理**:`deleted=true` 且 `updatedAt` 超过 N 天(如 30 天,确保所有设备都已同步过)后,真正物理删除。
- 这要求 v1 的删除逻辑改造:Repository 删除 = 软删除(本地 UI 过滤掉 `deleted` 行)。需配套 migration 加列。

## 6. 安全设计(v2 重点)

### 6.1 三层密钥的清晰边界
| 数据位置 | 加密方式 | 密钥 |
|---|---|---|
| 本地 Room 敏感字段 | v1 不变,设备 Keystore AES-GCM | 设备主密钥(不可导出)|
| WebDAV 端点密码 | 设备 Keystore | 同上,**不上传** |
| 上传的同步包 | 同步口令派生 AES-GCM(Argon2id)| 用户同步口令,**不绑定设备** |

核心铁律:**设备 Keystore 密文永不离开设备**;上传的一切由「用户同步口令」保护。

### 6.2 同步口令丢失 = 数据无法恢复
- 这是端到端加密的代价,必须在 UI 明确告知:**忘记同步口令,云端备份无法解密**,a-ssh 无法找回。
- 建议提供「导出恢复短语/提示」入口,但口令本身绝不上传。

### 6.3 KnownHost 是否同步
- 默认**不同步** host key 指纹:它是「本设备对服务器身份的信任记录」,跨设备传播可能掩盖某台设备遭遇的 MITM。
- 提供开关让高级用户选择同步(便于新设备免再次 TOFU 确认),默认关闭并说明风险。

### 6.4 传输层
- 强制 HTTPS;若用户填了 `http://` 明确警告(同步包虽已 E2E 加密,但端点凭据走 Basic Auth,明文 HTTP 会泄露)。
- 自签证书:不默认信任。提供「固定证书指纹(pinning)」高级选项,让自建用户手动信任,而非全局关校验。

## 7. 自动同步(WorkManager)

```kotlin
class SyncWorker(ctx: Context, params: WorkerParameters) : CoroutineWorker(ctx, params) {
    override suspend fun doWork(): Result {
        val pass = SyncPassphraseCache.get() ?: return Result.success() // 未缓存口令则跳过
        return try { engine.sync(pass); Result.success() }
        catch (e: RemoteChangedException) { Result.retry() }
        catch (e: IOException) { Result.retry() }
        catch (e: Exception) { Result.failure() }
    }
}
```
- 周期任务:`PeriodicWorkRequest`,最小间隔 15 分钟(系统限制),约束 `NetworkType.CONNECTED`(可选仅 WiFi)。
- 触发点:App 启动、配置变更后延迟触发、用户手动「立即同步」。
- 自动同步需要口令常驻 → 用户须显式开启「记住同步口令」(用 v1 Keystore 加密缓存)。不开启则只能手动同步时输入。

- 同步中:进度(下载/合并/上传三阶段)。
- 结果:新增/更新/删除计数;失败给可读原因(口令错、网络、端点错、版本冲突)。
- 主屏可加一个同步状态小图标(已同步/有改动待同步/出错)。

### 8.3 首次接入新设备的引导
新设备:填 WebDAV 配置 → 输入同步口令 → 「从云端恢复」→ 拉取并解密 → 写入本地。引导用户理解「本地空 + 云端有」时的首次导入。

## 9. 对 v1 的改造清单(迁移)

> v2 不是纯增量,有几处必须回头改 v1 的数据层。集中列出避免遗漏:

| 改造点 | 内容 | 风险 |
|---|---|---|
| 实体加 `uuid` | Host/Key/Command 三表加稳定 uuid 列 | 需 Room migration v1→2,为存量数据补 uuid |
| 软删除 | 三表加 `deleted` + 确保有 `updatedAt` | 删除逻辑改为置位;所有查询加 `WHERE deleted=0` 过滤 |
| Repository id↔uuid 映射 | Host.keyId(Long) ↔ KeyDto.keyRef(uuid) 双向翻译 | 导入时若引用的 key 不存在要处理(置空或保留待补)|
| `updatedAt` 维护 | 每次增改都刷新 updatedAt | 容易漏,集中在 Repository 写入口统一处理 |

建议:这些列其实在 v1 阶段就**预埋**最省事(uuid/updatedAt/deleted 三列即使 v1 用不到也先建好),可避免 v2 的破坏性迁移。若 v1 已上线,则老老实实写 migration。

## 10. 开发里程碑(v2)

1. **数据层迁移**:三表加 uuid/deleted/updatedAt,写 migration,Repository 改软删除 + updatedAt 维护。
2. **VaultDto + Codec**:序列化结构、id↔uuid 映射、`exportSnapshot/applySnapshot`(先不加密,本地导出 JSON 文件验证往返一致)。
3. **VaultCrypto**:Argon2id 派生 + AES-GCM,单测「加密→解密」往返、错口令报错。
4. **WebDavClient**:封装动词,设置页「测试连接」打通一台真实网盘(建议先用 Nextcloud/坚果云验证)。
5. **SyncEngine 单向**:先实现「全量推送」和「全量拉取覆盖」,跑通端到端加密上传/下载。
6. **MergeStrategy LWW**:三方合并 + 软删除,造数据测各种冲突分支。
7. **乐观锁 + 重试**:If-Match/412 处理,模拟双设备并发。
8. **UI**:同步设置页、状态反馈、新设备恢复引导。
9. **自动同步**:WorkManager 周期任务 + 口令缓存开关。
10. **安全收尾**:HTTPS 强制、口令丢失告知、KnownHost 同步开关、墓碑清理任务。

## 11. 风险与注意事项

1. **跨设备主键**:v1 自增 id 不能跨设备,uuid 改造是 v2 地基,先做。
2. **同步口令不可找回**:E2E 加密本质,UI 必须反复强调。
3. **时钟漂移影响 LWW**:多设备时间不准会误合并,需提示 + 可选「冲突询问」兜底。
4. **网盘 ETag 不统一**:坚果云等不返回稳定 ETag,需 `vaultVersion` 兜底并发检测。
5. **Argon2 内存占用**:低端机 64MB 可能 OOM/慢,提供降级档。
6. **半同步态**:单文件原子上传避免;切勿拆成多文件逐个 PUT。
7. **明文凭据生命周期**:VaultDto 含明文私钥/密码,内存中短暂存在,加密后立即释放,严禁写日志/缓存到磁盘明文。
8. **软删除复活 bug**:物理删除会被旧记录复活,务必走墓碑机制。
9. **HTTP 明文端点**:同步包虽加密,但 Basic Auth 凭据会泄露,强制/警告 HTTPS。
