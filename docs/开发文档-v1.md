# a-ssh Android SSH 客户端 — 开发文档 (v1)

> 本文档面向 **v1 范围(功能 1–6)**,目标是你在 Android Studio 中照此独立实现。
> 7–9(WebDAV / AI Agent / 自定义 AI API)不在 v1 实现,但本文在数据层与模块划分上预留扩展点,见最后一章。

## 0. 关键决策(已确认)

| 决策点 | 选择 | 后果 |
|---|---|---|
| 终端模拟器 | Termux `terminal-emulator` + `terminal-view` | **整个 App 必须以 GPLv3 发布并开源**。商店上架需附源码链接,不能闭源商用 |
| 凭据加密 | Android Keystore **硬件级**(StrongBox / TEE) | 主密钥不出安全芯片;部分老设备无 StrongBox 需降级到 TEE,代码要做能力探测 |
| SSH 库 | sshj | 现代算法、ed25519、known_hosts 原生支持 |
| UI | Jetpack Compose + 终端处用 AndroidView 内嵌 | 终端是 Canvas 绘制,不走 Compose |
| 数据库 | Room | 配置/私钥/自定义命令持久化 |

### GPLv3 合规要点(必须遵守,否则违反 Termux 许可)
1. 仓库根目录放置完整 `LICENSE`(GPLv3 全文)。
2. 每个引入/修改的源文件保留版权头。
3. 发布的 APK 必须能让用户获取**对应版本的完整源码**(附公开仓库链接即可)。
4. 不得在 GPLv3 之上再叠加更严格的限制(包括商店的某些专有条款,Google Play 可以,但要附源码声明)。

### 2.1 为什么 Termux 模块要"复制进来"而不是 Maven 依赖
Termux 没把 `terminal-view` 发布到 Maven Central 的稳定坐标。最稳妥做法:
1. 从 `https://github.com/termux/termux-app` 拉取源码。
2. 把 `terminal-emulator/` 和 `terminal-view/` 两个目录复制进本工程。
3. 在 `settings.gradle.kts` 用 `include(":terminal-emulator", ":terminal-view")` 引入。
4. `app` 依赖这两个模块:`implementation(project(":terminal-view"))`(它内部依赖 emulator)。

> 注意:这两个模块用的是 Java + 旧 AndroidView 体系,无需 Compose。复制后可能要把它们的 `compileSdk`/`namespace` 对齐到本工程版本,并删掉对 Termux 其它模块(如 `termux-shared`)的引用——`terminal-emulator`/`terminal-view` 本身依赖很轻。

### 3.1 sshj 在 Android 上的坑(务必处理)
- sshj 默认依赖 **BouncyCastle**。Android 自带一个被裁剪的 BC(`org.bouncycastle`),容易冲突。处理:
  - 在 app `build.gradle.kts` 用完整版 `org.bouncycastle:bcprov-jdk18on` 并在 `Application.onCreate` 里:
    ```kotlin
    Security.removeProvider("BC")
    Security.insertProviderAt(BouncyCastleProvider(), 1)
    ```
  - 若仍冲突,考虑对 BC 做 `packagingOptions`/`exclude`,或用 sshj 文档推荐的 Android 配置。
- sshj 还可选依赖 `eddsa`(net.i2p.crypto:eddsa)以支持 ed25519,以及 `slf4j`。加上:
  ```kotlin
  implementation("net.i2p.crypto:eddsa:0.3.0")
  implementation("org.slf4j:slf4j-android:1.7.36") // 或 nop,避免日志告警
  ```
- `R8/Proguard`:sshj 通过反射加载算法实现,release 构建要加 keep 规则(见 §13.2)。

data class HostEntity(

## 5. 整体架构

采用 **单向数据流**:UI(Compose)→ ViewModel(StateFlow)→ Repository → (Room / SSH 层 / Crypto)。

```
Compose Screen ──事件──> ViewModel ──> Repository ──┬─> Room DAO
      ▲                      │                       ├─> CryptoManager (Keystore)
      └──── StateFlow ───────┘                       └─> SshConnectionManager
                                                              │
                                            SshForegroundService 持有会话
                                                              │
                                                  SshTerminalSession ↔ TerminalView
```

- **CryptoManager**:统一负责加解密,Repository 存取敏感字段前后过它。
- **SshConnectionManager**:进程内单例(或由 Service 持有),管理活跃 `SshSession` 的 Map(key = hostId),支持复用、断线检测、重连。
- 终端 UI 不直接碰 sshj,只跟 `SshTerminalSession`(实现 Termux 的 `TerminalSession` 抽象)交互。

## 6. 凭据加密(Keystore 硬件级)

### 6.1 设计
- 在 Android Keystore 生成一把 **AES-256-GCM** 主密钥,别名 `assh_master_key`。
- 设备支持时启用 **StrongBox**(独立安全芯片,API 28+);不支持回退到 TEE。
- 每条敏感数据(密码 / 私钥 / 私钥口令)单独加密:GCM 每次随机 12 字节 IV,密文格式 `[1B version][12B IV][ciphertext+tag]`,整体作为 BLOB 存 Room。
- 主密钥永不导出,加解密都在 Keystore 内完成。

> 不直接用 `androidx.security:security-crypto`(EncryptedSharedPreferences/EncryptedFile),因为:它面向"文件/Prefs 整体加密",而我们要的是**字段级密文存进 Room**,自管 IV 更灵活。security-crypto 也已进入维护停滞期。所以自己用 Keystore 包一层更可控。

### 6.2 主密钥生成
```kotlin
object CryptoManager {
    private const val KEY_ALIAS = "assh_master_key"
    private const val ANDROID_KS = "AndroidKeyStore"
    private const val TRANSFORM = "AES/GCM/NoPadding"
    private const val GCM_IV_LEN = 12
    private const val GCM_TAG_BITS = 128

    private val keyStore = KeyStore.getInstance(ANDROID_KS).apply { load(null) }

    fun ensureKey(context: Context) {
        if (keyStore.containsAlias(KEY_ALIAS)) return
        val builder = KeyGenParameterSpec.Builder(
            KEY_ALIAS,
            KeyProperties.PURPOSE_ENCRYPT or KeyProperties.PURPOSE_DECRYPT
        )
            .setBlockModes(KeyProperties.BLOCK_MODE_GCM)
            .setEncryptionPaddings(KeyProperties.ENCRYPTION_PADDING_NONE)
            .setKeySize(256)
            // 不设 setUserAuthenticationRequired(true),否则每次解密都要生物认证;
            // 如需"打开 App 才能解密",可单独做一把需认证的密钥。见 §6.4
        // StrongBox 能力探测
        val hasStrongBox = context.packageManager
            .hasSystemFeature(PackageManager.FEATURE_STRONGBOX_KEYSTORE)
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.P && hasStrongBox) {
            builder.setIsStrongBoxBacked(true)
        }
        val kpg = KeyGenerator.getInstance(KeyProperties.KEY_ALGORITHM_AES, ANDROID_KS)
        try {
            kpg.init(builder.build()); kpg.generateKey()
        } catch (e: StrongBoxUnavailableException) {
            // 某些机型谎报 StrongBox,捕获后降级
            builder.setIsStrongBoxBacked(false)
            kpg.init(builder.build()); kpg.generateKey()
        }
    }

    private fun secretKey(): SecretKey =
        (keyStore.getEntry(KEY_ALIAS, null) as KeyStore.SecretKeyEntry).secretKey

    fun encrypt(plain: ByteArray): ByteArray {
        val cipher = Cipher.getInstance(TRANSFORM)
        cipher.init(Cipher.ENCRYPT_MODE, secretKey())
        val iv = cipher.iv                       // GCM 自动生成
        val ct = cipher.doFinal(plain)
        return ByteBuffer.allocate(1 + iv.size + ct.size)
            .put(1.toByte()).put(iv).put(ct).array()
    }

    fun decrypt(blob: ByteArray): ByteArray {
        val buf = ByteBuffer.wrap(blob)
        val version = buf.get()                  // 预留版本位
        val iv = ByteArray(GCM_IV_LEN); buf.get(iv)
        val ct = ByteArray(buf.remaining()); buf.get(ct)
        val cipher = Cipher.getInstance(TRANSFORM)
        cipher.init(Cipher.DECRYPT_MODE, secretKey(), GCMParameterSpec(GCM_TAG_BITS, iv))
        return cipher.doFinal(ct)
    }
}
```

### 6.3 与 Repository 配合
```kotlin
// 存:
val host = base.copy(encPassword = password?.let { CryptoManager.encrypt(it.toByteArray()) })
// 取(连接时才解密,UI 列表不解密):
val password = host.encPassword?.let { String(CryptoManager.decrypt(it)) }
```
> 原则:**密文常驻,明文瞬时**。明文只在"即将建立连接"时解密,用完不缓存(或仅在内存 `CharArray` 中,用完清零)。

### 6.4 可选增强(v1 可不做,但预留)

- `setUnlockedDeviceRequired(true)`:仅设备解锁状态可用。

## 7. SSH 连接层(sshj 封装)

### 7.1 SshSession — 单个连接
职责:持有一个 sshj `SSHClient` + 一个交互式 `Session.Shell`(PTY)。
```kotlin
class SshSession(val hostId: Long) {
    private val client = SSHClient()
    private lateinit var shell: Session.Shell
    lateinit var stdout: InputStream
    lateinit var stdin: OutputStream

    val state = MutableStateFlow(ConnState.IDLE) // IDLE/CONNECTING/CONNECTED/DISCONNECTED/ERROR

    suspend fun connect(cfg: ResolvedHostConfig) = withContext(Dispatchers.IO) {
        state.value = ConnState.CONNECTING
        client.addHostKeyVerifier(AsshHostKeyVerifier(cfg.hostId, knownHostDao))
        client.connectTimeout = 15_000
        client.timeout = 0                      // 交互会话不超时
        client.connect(cfg.host, cfg.port)
        when (cfg.authType) {
            AuthType.PASSWORD -> client.authPassword(cfg.username, cfg.password)
            AuthType.KEY      -> {
                val kp = loadKeyProvider(cfg.privateKeyPem, cfg.passphrase) // sshj KeyProvider
                client.authPublickey(cfg.username, kp)
            }
        }
        val session = client.startSession()
        session.allocatePTY("xterm-256color", cols, rows, 0, 0, emptyMap())
        shell = session.startShell()
        stdout = shell.inputStream
        stdin  = shell.outputStream
        state.value = ConnState.CONNECTED
    }

    fun write(bytes: ByteArray) { stdin.write(bytes); stdin.flush() }
    fun resize(cols: Int, rows: Int) { shell.changeWindowDimensions(cols, rows, 0, 0) }
    fun close() { runCatching { shell.close() }; runCatching { client.disconnect() } }
}
```
- PTY 类型用 `xterm-256color` 与终端 View 对齐。
- `allocatePTY` 的 cols/rows 初始值随便给(如 80×24),终端 View 一渲染就 resize 到真实尺寸。

### 7.2 ResolvedHostConfig — 解密后的瞬时配置
Repository 把 `HostEntity` + 关联 `KeyEntity` 解密,组装成只在内存存在的 `ResolvedHostConfig`(含明文密码/私钥)。连接建立后即可丢弃明文引用。

### 7.3 Host Key 校验(安全,别跳过)
首次连接记录指纹到 `known_hosts` 表;再次连接比对。指纹变化 → 抛出,UI 弹窗让用户确认(可能是中间人,也可能是服务器重装)。**不要无脑 PromiscuousVerifier 接受所有**——那等于关掉 MITM 防护,只在用户明确"信任"时才接受。
```kotlin
class AsshHostKeyVerifier(...) : HostKeyVerifier {
    override fun verify(hostname: String, port: Int, key: PublicKey): Boolean {
        val fp = SecurityUtils.getFingerprint(key) // sshj 提供
        val saved = dao.find("$hostname:$port")
        return when {
            saved == null -> { dao.insert(...); true }        // TOFU 首次信任
            saved.fingerprintSha256 == fp -> true
            else -> false                                      // 变更 → 上层处理/弹窗
        }
    }
    // sshj 0.39 的 findExistingAlgorithms 可返回已知算法,按需实现
}
```

### 7.4 SshConnectionManager — 多连接管理 + 重连(功能 6)
```kotlin
class SshConnectionManager {
    private val sessions = ConcurrentHashMap<Long, SshSession>()

    fun get(hostId: Long): SshSession? = sessions[hostId]

    suspend fun connect(cfg: ResolvedHostConfig): SshSession {
        sessions[cfg.hostId]?.takeIf { it.state.value == ConnState.CONNECTED }?.let { return it }
        val s = SshSession(cfg.hostId)
        sessions[cfg.hostId] = s
        s.connect(cfg)
        return s
    }

    suspend fun reconnect(hostId: Long, cfg: ResolvedHostConfig): SshSession {
        sessions[hostId]?.close()
        return connect(cfg) // 复用缓存的 cfg(凭据已在内存或重新解密)
    }

    fun disconnect(hostId: Long) { sessions.remove(hostId)?.close() }
}
```
重连策略(功能 6):
- 连接配置 + 解密后的凭据缓存在 ViewModel/Service,断线后"重新连接"按钮一键调用 `reconnect`,无需用户重新填表/输密码。
- 可选自动重连:监听 `state == DISCONNECTED` 且非用户主动断开 → 指数退避重试(1s,2s,4s,上限 30s)。v1 先做手动一键重连,自动重连留开关。

## 8. 终端集成(Termux 模块桥接)

### 8.1 核心关系
Termux 的 `TerminalView`(一个自定义 `View`)负责渲染与输入,它需要一个 `TerminalSession`。`TerminalSession` 在 Termux 原设计里是 fork 本地子进程;我们要**不启动本地进程**,而是把它的 IO 接到 SSH 流上。

两种做法:
- **A. 直接实现 `TerminalSession` 的子类**,覆盖其与底层进程交互的部分,把 stdin/stdout 改接 SSH。`TerminalSession` 内部有 `TerminalEmulator` 负责 ANSI 解析,这部分照用。
- **B. 复用 `TerminalEmulator` + `TerminalView`,自己写一个轻封装** `SshTerminalSession`,持有 emulator,把 SSH `stdout` 喂给 `emulator.append(bytes, len)`,把 View 的按键回调写进 SSH `stdin`。

推荐 **B**,边界更清晰,不被 Termux `TerminalSession` 的进程假设绑死。

### 8.2 数据流
```
SSH stdout ──读线程──> emulator.append(buf, n) ──> terminalView.onScreenUpdated()(主线程 post)
TerminalView 按键/IME ──> client 回调 ──> sshSession.write(bytes)
TerminalView 尺寸变化(onSizeChanged) ──> 计算 cols/rows ──> emulator.resize + sshSession.resize
```

### 8.3 关键骨架
```kotlin
class SshTerminalSession(
    private val ssh: SshSession,
    rows: Int, cols: Int
) {
    val emulator = TerminalEmulator(/* client */ TermClient(), cols, rows, /*transcriptRows*/ 2000)
    private var readJob: Job? = null

    fun start(scope: CoroutineScope) {
        readJob = scope.launch(Dispatchers.IO) {
            val buf = ByteArray(8192)
            while (isActive) {
                val n = ssh.stdout.read(buf)
                if (n <= 0) break
                withContext(Dispatchers.Main) {
                    emulator.append(buf, n)
                    onUpdate?.invoke()
                }
            }
            withContext(Dispatchers.Main) { onDisconnected?.invoke() }
        }
    }
    fun write(text: String) = ssh.write(text.toByteArray())
    fun resize(cols: Int, rows: Int) { emulator.resize(rows, cols); ssh.resize(cols, rows) }
    fun stop() { readJob?.cancel() }

    var onUpdate: (() -> Unit)? = null
    var onDisconnected: (() -> Unit)? = null
}
```
> 注:`TerminalEmulator`/`TerminalView` 的精确 API(构造参数、`TerminalSessionClient`/`TerminalViewClient` 接口方法名)以你复制进来的 Termux 源码版本为准——**复制后先读它们的 public 接口**,本骨架是结构示意。`TerminalView` 需要你实现 `TerminalViewClient`(处理单击、长按选择、复制粘贴回调等)。

### 8.4 在 Compose 里嵌入
```kotlin

    AndroidView(factory = { ctx ->
        TerminalView(ctx, null).apply {
            setTerminalViewClient(vm.viewClient)

        }
    }, modifier = Modifier.fillMaxSize())
    // 上方/下方叠加快捷工具条(见 §9.3)
}
```

## 9. UI 设计(Compose)

### 9.1 导航与屏幕

### 9.2 服务器编辑表单(功能 1、2、3)
字段:label、host、port、username、认证方式单选(密码 / 私钥)。
- 选密码:密码输入框(可留空 → 连接时再问)。
- 选私钥:下拉选 `KeyEntity.alias`(功能 3 的"通过别名选择"),+ 可选私钥口令。
- 高级:字符集、登录后自动执行命令。

### 9.3 终端工具条(功能 5 的核心)
终端是软键盘的痛点。要在终端上/下方放一条可横滑的**快捷键工具条**:
- 固定特殊键:`Esc Tab Ctrl Alt ↑ ↓ ← → Home End PgUp PgDn / - | ~`
  - `Ctrl`/`Alt` 做成**粘滞键**:点一下高亮,下个字母与之组合(发送 `Ctrl+C` = 0x03 等)。控制字符映射:`Ctrl + 字母` → `字母大写 ASCII - 64`。
- 复制 / 粘贴按钮:
  - 复制:`TerminalView` 长按进入选择模式,选中文本 → 写入系统剪贴板(`ClipboardManager`)。
  - 粘贴:读剪贴板 → `termSession.write(text)`。
- 自定义命令区:横向滚动的 `Chip`/按钮,数据来自 `CommandEntity`(全局 + 当前 host)。点击 → `write(command + if(appendEnter) "\n" else "")`。长按 → 编辑/删除。
- "+":弹窗新增自定义命令(label + command + 是否回车 + 作用域)。

### 9.4 终端屏幕状态条(功能 6)
顶部显示连接状态(已连接 / 连接中 / 已断开)。断开时显示醒目的**「重新连接」**按钮,一键调用 `reconnect`。

### 9.5 ViewModel 模式
- `TerminalViewModel(hostId)`:持有 `SshTerminalSession`、连接状态 `StateFlow`、自定义命令列表 `Flow`。
- 输入事件(工具条按键、命令点击、粘贴)统一走 VM 方法 → `termSession.write(...)`。

## 10. 前台 Service 与保活(功能 6 关键支撑)

为什么要前台 Service:Android 在 Activity 退到后台后可能回收进程,导致 SSH 会话被杀。把活跃会话交给 **前台 Service** 持有,挂持久通知,系统不轻易杀。

### 10.1 SshForegroundService
```kotlin
class SshForegroundService : LifecycleService() {
    private val manager = SshConnectionManager() // 或注入单例
    override fun onStartCommand(...): Int {
        startForeground(NOTI_ID, buildNotification()) // 显示活跃连接数
        return START_STICKY
    }
    // 提供 binder 让 Activity 拿到 manager / 各 session
}
```
- 通知渠道:`IMPORTANCE_LOW`,内容"已连接 N 台服务器",带"全部断开"操作。
- `START_STICKY`:进程被杀后系统尝试重启 Service(此时会话已断,但可触发自动重连)。
- 退出时机:无活跃会话 → `stopForeground` + `stopSelf`。

### 10.2 版本兼容
- API 34+(targetSdk 34+):`startForeground` 必须声明 `foregroundServiceType`。最贴近的是 `dataSync` 或 `specialUse`(`specialUse` 需在 manifest 写理由,上架要审)。SSH 持久连接没有完全对口的类型,**建议 `dataSync`**,并在文档中说明用途。
- 权限:`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_DATA_SYNC`(34+)、`POST_NOTIFICATIONS`(33+,运行时申请)。

### 10.3 断线检测
- 读线程 `stdout.read()` 返回 -1 或抛 IOException → 标记 `DISCONNECTED` → 更新通知 + UI。
- 心跳:sshj 可设 `client.connection.keepAlive.keepAliveInterval = 30`,检测半开连接。

按依赖关系排,每步可独立验证:

8. **终端桥接**(功能 4):把 §7 的 SSH 流接到 §8 的 emulator/View,实现真正可交互终端。处理 resize、字符集。

## 15. 为 7–9 预留的扩展点(v1 不实现,仅设计)

|---|---|
| 7 WebDAV 同步 | 数据层加 `SyncProvider` 接口抽象,配置导出为可序列化 DTO(敏感字段保持密文或导出时用用户口令重加密)。新增独立 `:sync` 模块即可,不动核心。 |

## 16. 风险与注意事项汇总

1. **GPLv3 传染**:已确认接受。发布必须开源 + 附源码。
2. **本机无法命令行编译**:JDK 26 / 旧 SDK。务必用 Android Studio + 内置 JDK 17 + 自动下载 SDK 35。
3. **Termux 模块 API 因版本而异**:§8 骨架是结构示意,复制源码后以实际 public 接口为准。
4. **BouncyCastle 冲突**:Android 自带裁剪版 BC,需替换 provider + packaging 排除。
5. **sshj minify**:release 必须配 keep 规则,否则反射加载算法失败。
6. **前台 Service 类型**:targetSdk 34+ 的 `foregroundServiceType` 选 `dataSync`,上架需说明。
7. **明文凭据生命周期**:解密后的密码/私钥只在内存瞬时存在,用完清理,不写日志。
8. **Host key 校验**:别图省事用 PromiscuousVerifier,会丢失 MITM 防护。
9. **软键盘遮挡**:`adjustResize` + IME insets,终端和工具条要随键盘移动。
